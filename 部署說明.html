把紀錄器放上 GitHub

工作表與網站程式已完成。正式雲端同步還需要：GitHub Pages 網址，以及你的 Google 網頁用戶端 ID。

先試用介面 · 開啟你的試算表

1. 先保護試算表

  1. 開啟試算表，按右上角「共用」。
  2. 將「一般存取權」設為「限制」，按「完成」。如果已是限制，不必再改。
  3. 保留自己的擁有者權限；手機與電腦都使用這個 Google 帳號。

GitHub 網站可以公開，但復健紀錄應放在受限制的試算表。不要將訓練 CSV、JSON 備份或 OAuth client secret 上傳 GitHub。

2. 上傳 GitHub 網站

  1. 登入 GitHub，建立新儲存庫。建議名稱：neck-workout-tracker。一般免費帳號可選 Public；不要開啟既有計算網站的儲存庫來覆蓋。
  2. 解壓縮交付的 ZIP。上傳 index.html、style.css、config.js、core.js、app.js、部署說明.html 六個檔案至儲存庫最上層（根目錄）。不是上傳 ZIP，也不要多包一層資料夾。
  3. 按「Commit changes」儲存。
  4. 進入 Settings → Pages。Source 選「Deploy from a branch」，Branch 選 main，資料夾選 / (root)，按 Save。
  5. 等部署完成，開啟 Pages 顯示的網站網址。通常形如 https://你的帳號.github.io/neck-workout-tracker/；以 GitHub 顯示的網址為準。

此時網頁可以顯示，但尚不能同步，這是正常的。

GitHub 官方發布來源設定

3. 建立 Google 登入設定（只做一次）

  1. 用持有試算表的帳號登入 Google Cloud Console，建立或選擇專用專案，例如「頸肩訓練紀錄器」。這個方案不使用付費主機或服務帳戶。
  2. 在「API 和服務 → 程式庫」搜尋 Google Sheets API，按啟用。
  3. 進入 Google Auth Platform 設定應用程式名稱、支援信箱及聯絡信箱（填自己的信箱）。個人 Gmail 選 External／外部。
  4. 在 Audience／目標對象保留 Testing／測試中，將自己的 Google 帳號加入 Test users／測試使用者。
  5. 在 Data Access／資料存取加入範圍 https://www.googleapis.com/auth/spreadsheets。這是試算表讀寫權限，授權範圍可涵蓋帳號可存取的試算表；本站程式只使用設定中的這一份。請只部署自己信任的程式碼。
  6. 進入 Clients／用戶端 → Create client／建立用戶端，類型選 Web application／網頁應用程式。
  7. Authorized JavaScript origins／已授權的 JavaScript 來源填入 Pages 的來源，例如 https://你的帳號.github.io。不要加 /neck-workout-tracker/，也不要加結尾斜線。若使用自訂網域，填實際網域。
  8. 本方案是彈出視窗授權，不需要填 Authorized redirect URIs。
  9. 建立後複製結尾為 .apps.googleusercontent.com 的 Client ID／用戶端 ID。這個 ID 可放在前端；Client secret 不需要使用，不可公開。

若公司或學校帳號限制授權，需由該帳號管理員允許。測試模式可能出現未驗證應用程式提醒；先核對是自己建立的專案與正確帳號，依 Google 當下顯示的授權規則處理。正式對外提供多人使用需另處理 Google 驗證要求。

Google 官方設定說明 · Google 官方前端授權方式

4. 把用戶端 ID 貼回 GitHub

  1. 在 GitHub 儲存庫打開 config.js，按鉛筆編輯。
  2. 找到 clientId: ''，改為 clientId: '你剛複製的用戶端ID'。保留引號與逗號。試算表 ID 已填好，不必更改。
  3. 按 Commit changes。等 Pages 部署完成，再重新載入網站。
  4. 按「登入 Google 並連線」，選持有試算表的帳號並完成授權。

不需要 Apps Script，不需要部署匿名可寫入的 Web App，也不用放私人金鑰。

5. 手機與電腦同步驗收

  1. 手機開正式網站（網址不要有 ?demo=1），登入後選今天日期。
  2. 勾選實際完成的動作，等待顯示「已同步」。
  3. 電腦開同一網址、登入同一帳號，確認看到相同勾選。
  4. 電腦填入實際 RPE，等「已同步」。手機按「重新整理／重試」，確認相同數值。
  5. 開試算表「每日紀錄」確認內容；「每月統計」確認年度 B2 正確。
  6. 手機可將正式網站加入主畫面。每次重新開頁面需要重新連線，登入逾期時也需再次登入。

網頁前景每 60 秒重新讀取一次，切回頁面也會刷新；按鈕可立即刷新。只有收到 Google 成功寫入並重新讀回後，才會顯示「已同步」。

平常怎麼使用

  • 每日紀錄與每月統計是自動計算，不要直接改公式。勾選、RPE、備註由網站輸入。
  • 動作設定可改中文／英文名稱、組次及提示。保留 ex0–ex5 代碼與六列順序，不要換成不同動作來重用舊代碼。
  • 同步紀錄保留每次欄位變更。不要排序、刪除、修改或插入空白列；順序決定最後版本。同一欄位以最後抵達雲端者為準。
  • RPE 可留白；0 是有效數值。只有備註或 RPE、沒有完成動作的日期不算訓練日。
  • 「匯入舊版備份」支援原紀錄器的 JSON 與新版備份。只新增雲端沒有的日期，跳過已有日期。匯入期間避免其他裝置同時新增相同日期。
  • 斷線或權杖到期時，未送出變更只在本頁記憶體；保持頁面開啟，重新登入後重試。關閉分頁或手機回收頁面可能遺失待同步變更。可先按「備份全部資料」。
  • JSON 備份內的 pendingChanges 保留未送出原始變更；一般匯入不覆寫已存在日期，因此若要恢復既有日期的未同步修改，請對照備份在網站重填。
  • CSV 可用 Excel 開啟；完整備份含個人紀錄，請保存在自己的裝置。
  • 每日彙整預留 3999 個日期；接近上限時在「每日紀錄」最下方新增列，公式使用整欄參照。大量多年紀錄可能需要後續分檔。

問題排除

  • origin_mismatch：檢查 Google 用戶端來源是否等於目前網址的「https://網域」，不要含路徑；設定更新可能需等待。
  • 403：確認 Sheets API 已啟用、帳號是測試使用者且對試算表有編輯權限，並同意試算表授權。
  • 401／登入到期：重新登入後按重試，不必重新部署。
  • 404：GitHub Pages 確認 main → / (root)，根目錄有 index.html，並查看 Actions 部署結果。
  • 不能登入：不要用 file:// 直接開檔案作正式連線。使用 GitHub Pages HTTPS 網址。允許 Google 登入彈出視窗，避免在通訊軟體內建瀏覽器操作。
  • 本機測試：以 HTTP 伺服器開啟 localhost；Google 已授權來源需另外加入 http://localhost 與包含實際連接埠的來源。
